# STS - Unreal Engine Deckbuilding Combat Portfolio

## 프로젝트 개요

STS는 Slay the Spire 스타일의 턴제 덱빌딩 전투 시스템을 Unreal Engine 5 기반으로 구현한 개인 포트폴리오 프로젝트입니다.

카드 드로우, 디스카드, 에너지, 적 Intent, 상태효과, 피해 예측 UI, 카드 보상, 카드 강화, 보스 전투까지 이어지는 전투 루프를 구현하는 데 중점을 두었습니다.

본 프로젝트는 상용 게임 수준의 콘텐츠 양보다, 턴제 카드 전투의 핵심 시스템을 C++과 UMG로 직접 구현하고 UI와 게임 로직을 동기화하는 데 초점을 두었습니다.

## 주요 구현 기능

### 1. 턴 기반 전투 시스템

- 플레이어 턴 / 적 턴 / 승리 / 패배 상태 관리
- 에너지 기반 카드 사용
- 턴 종료 시 손패 디스카드
- 적 턴 행동 후 플레이어 턴 재개
- 전투 승리 시 보상 화면으로 전환

---

### 2. 카드 시스템

- `MasterDeck`, `DrawPile`, `DiscardPile` 구조 구현
- 전투 시작 시 `MasterDeck`을 기준으로 `DrawPile` 초기화
- 카드 사용 또는 턴 종료 시 `DiscardPile`로 이동
- `DrawPile`이 비었을 경우 `DiscardPile`을 셔플하여 다시 `DrawPile`로 복귀
- DataTable 기반 카드 데이터 관리

---

### 3. 카드 드래그 & 타겟팅 UI

- UMG Drag & Drop 기반 카드 사용
- 공격 카드 드래그 시 타겟팅 화살표 표시
- 마우스 위치와 적 위치를 기반으로 가장 가까운 타겟 탐색
- 타겟된 적 하이라이트 처리
- 드래그 중 적 HP 예측 UI 갱신

---

### 4. 피해 예측 UI

- 카드 사용 전 적 HP가 얼마나 감소할지 미리 표시
- 적의 방어도, 취약 상태 반영
- 플레이어의 힘, 약화 상태 반영
- 카드 설명 텍스트도 실제 예상 피해량 기준으로 동적 갱신

예시:

- 기본 피해량 6
- 적이 취약 상태일 경우 예상 피해량 9로 표시
- 적 HP 예측 UI도 동일한 값 기준으로 갱신

---

### 5. 상태효과 시스템

구현한 상태효과:

- `Vulnerable`  
  적이 받는 피해 증가

- `Weak`  
  플레이어가 가하는 피해 감소

- `Strength`  
  플레이어가 가하는 피해 증가

상태효과는 전투 중 UI와 피해 계산에 반영되며, 턴 진행 또는 전투 종료 시 갱신됩니다.

---

### 6. 적 Intent 시스템

- 적이 다음 턴 행동을 미리 결정
- 공격 / 방어 / 디버프 / 멀티히트 Intent 표시
- Intent에 따라 적 턴에 실제 행동 실행
- 보스는 일반 몬스터와 다른 멀티히트 패턴 보유

---

### 7. 카드 보상 시스템

- 전투 승리 후 랜덤 카드 보상 3장 제시
- 보상 가능 카드만 후보로 선정
- 선택한 카드는 `MasterDeck`에 영구 추가
- 다음 전투부터 새 카드가 덱에 포함됨

---

### 8. 카드 강화 시스템

- 휴식 노드에서 카드 강화 선택 가능
- 현재 덱 목록을 UI로 표시
- 선택한 카드를 강화된 카드 ID로 교체
- 강화된 카드는 이후 전투에서 변경된 수치로 사용됨

---

### 9. 맵 진행 및 보스 전투

- 전투 → 보상 → 노드 선택 → 다음 전투 흐름 구현
- 전투 노드와 휴식 노드 구분
- 보스 층 도달 시 보스 전투 진행
- 보스는 멀티히트 패턴을 통해 일반 몬스터와 차별화

---

## 기술적으로 신경 쓴 부분

### UI와 게임 로직 동기화

카드 사용 전 예상 피해량, 카드 설명 텍스트, 적 HP 예측 UI가 같은 계산 결과를 기반으로 갱신되도록 구현했습니다.

이를 통해 플레이어가 카드를 사용하기 전에 결과를 예측할 수 있도록 했습니다.

---

### 커스텀 카드 드래그 처리

UMG 기본 DragVisual 사용 시 RichTextBlock 레이아웃이 깨지는 문제가 발생했습니다.

이를 해결하기 위해 기본 DragVisual을 사용하지 않고, 별도의 카드 위젯을 Viewport에 직접 추가한 뒤 마우스 위치를 추적하는 방식으로 드래그 비주얼을 구현했습니다.

---

### Slate 기반 타겟팅 라인

`NativePaint`에서 Bezier Curve를 직접 계산하여 카드에서 적으로 향하는 타겟팅 화살표를 그렸습니다.

카드 위치, 마우스 위치, 적의 월드 좌표를 Widget Local 좌표로 변환하여 UI 상에서 자연스럽게 연결되도록 처리했습니다.

---

### DataTable 기반 카드 관리

카드 이름, 비용, 타입, 피해량, 방어도, 상태효과, 보상 가능 여부 등을 DataTable로 관리했습니다.

이를 통해 카드 추가와 수정이 코드 변경 없이 가능하도록 구성했습니다.

## 현재 구조의 한계 및 개선 방향

초기 프로토타입 단계에서는 전투 루프를 빠르게 검증하기 위해 GameMode에 전투 흐름, 덱, 보상, 맵 진행 일부를 집중시켰습니다.

기능이 확장되면서 GameMode의 책임이 커졌고, 장기적으로는 다음과 같이 분리하는 것이 더 적절하다고 판단했습니다.

- `CombatManager`  
  턴 흐름, 승리/패배 판단, 전투 시작/종료 관리

- `DeckManager`  
  `MasterDeck`, `DrawPile`, `DiscardPile`, 셔플, 보상 카드 추가 관리

- `StatusEffectComponent`  
  플레이어와 적이 공통으로 사용하는 상태효과 처리

- `AudioManager`  
  전투 BGM, 맵 BGM, 엔딩 BGM 전환 관리

현재 포트폴리오 마무리 단계에서는 안정성을 우선하여 대규모 리팩토링 대신 현재 구조를 유지했습니다.

## 프로젝트 목표

이 프로젝트의 목표는 단순히 카드 게임을 복제하는 것이 아니라, 턴제 카드 전투에서 필요한 핵심 시스템을 직접 구현하고, 게임 로직과 UI가 실시간으로 동기화되는 구조를 만드는 것이었습니다.
